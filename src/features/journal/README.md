# 내 기록 (성장일지 · 포트폴리오)

Figma 02-4의 일곱 화면입니다. `/me`(내 기록), `/me/journal/:id/edit`(성장일지 쓰기), `/me/journal/:id/organizing`(AI 정리 중), `/me/journal/:id/preview`(AI 정리 미리보기), `/me/journal/:id`(내 일지 상세), `/me?tab=portfolio`(포트폴리오), `/me/portfolio/:projectId?format=resume|paragraph`(요약 결과).

## 연결

- `app/router.tsx`에 `journalRoutes`를 합쳤습니다. 노트처럼 `AssignmentBoundary` 밖에 두었고, 운영진 라우트의 `/me` 준비 중 화면은 지웠습니다. 운영진 탭바의 내 기록 탭도 이 화면으로 이동합니다.
- 하단 탭의 내 기록은 `/me`로 이동하며 켜진 아이콘은 `@/assets/journal/nav-record-active.svg`입니다. 탭은 `?tab=portfolio` 쿼리라 두 탭 모두 하단 탭이 켜집니다.
- 홈: 이번 주 성장일지 쓰기 → `/me/journal/new?import=week`, 돌려받은 일지 고치기 → 돌려받은 일지 상세.
- 회의 정리 완료 화면의 성장일지 쓰기 → `/me/journal/new?import=week`.

## 흐름

1. `/me/journal/new`가 빈 일지(작성 중)를 만들고 바로 그 id의 쓰기 화면으로 바꿉니다. 배정 정보를 불러온 뒤 만들어서 내 파트 · 기수가 기본으로 채워집니다. 쓰는 도중 나가도 내 기록에 '작성 중'으로 남습니다.
2. 쓰기 화면은 고칠 때마다 저장하고 헤더에 '자동 저장됨'을 보여줍니다. 프로젝트 · 활동 · 시점 · 파트 · 막힌 것 · 넘긴 방법이 필수입니다. 빠진 칸이 있으면 칸마다 안내하고 첫 칸으로 스크롤합니다. 자유 메모는 나만 보고 정리본에 들어가지 않습니다.
3. AI 정리 중 화면은 네 단계를 차례로 보여준 뒤 미리보기로 바뀝니다(목이라 실제 정리는 즉시 끝남).
4. 미리보기에서 태그는 빼기만 됩니다(하나는 남김). 보완 질문은 건너뛰거나 답할 수 있고, 답은 '이렇게 넘겼어요'에 더해집니다. 검토 요청하면 검토 대기가 되고 내 기록으로 돌아갑니다.
5. 돌려받은 일지는 상세에서 운영진의 한 줄을 보고 '고쳐서 다시 내기'로 같은 id를 고쳐 다시 냅니다. 검토 대기 · 공개 중 일지는 쓰기 화면을 열면 상세로 돌아갑니다.

## 파일

- `types.ts`: MyJournal · OrganizedJournal · PortfolioSummary. 상태(PENDING/APPROVED/REJECTED) · 공개 범위(NOW/NEXT) · 행사 종류는 운영진 검토(`admin/types.ts`)와 같은 이름이고, 아직 내지 않은 일지는 DRAFT입니다. 시점은 노트 게시판과 같은 단위입니다.
- `mock/data.ts`: Figma 예시 일지 5개(읽음 20 · 도움돼요 8), 내 프로젝트 2개(p1은 운영진 목의 멋사수첩팀과 같은 id), 가릴 이름 목록, 하루 요약 횟수(5).
- `journalStore.ts`: 목 + localStorage `likelion-journals:v1`을 id로 합칩니다(회의 기록 recordStore와 같은 방식). 운영진 검토 화면과는 저장소를 공유하지 않습니다. 백엔드가 붙으면 같은 API로 합쳐집니다.
- `organize.ts`: AI 정리 · 포트폴리오 요약의 규칙 기반 목입니다. 팀원 이름은 `[팀원 A]`, 팀 이름은 `[우리 팀]`으로 가리고, 단어로 상황 태그를 고르고, 행사 · 시점 · 태그로 제목을 만듭니다(예: '중간발표 앞두고 의견이 갈렸을 때 정리한 방법'). 넘긴 방법이 짧거나 다시 한다면이 비면 보완 질문을 냅니다. 요약은 도움돼요가 많은 일지 순으로 문장을 고르고, 숫자가 없는 성과 자리에 `[결과 수치 입력]`을 넣습니다. 다시 만들기는 고르는 순서를 돌립니다.
- `portfolioStore.ts`: localStorage `likelion-portfolio:v1`에 프로젝트 · 형식별 마지막 요약과 오늘 만든 횟수를 둡니다. 날짜가 바뀌면 다시 5번입니다(실제 제한은 서버가 정함).
- `api.ts`: 화면이 부르는 함수입니다. 백엔드 · AI가 정해지면 각 함수의 내부만 교체하세요.
- `meetingImport.ts`: 이번 주(월~일, 브라우저 날짜) 회의 기록을 불러와 정한 것은 '어떻게 넘겼나'에, 할 일은 '자유 메모'에 이어 붙입니다. 이미 불러온 회의는 다시 넣지 않습니다.
- `useJournals.ts`: React Query 조회와 내 배정 정보(홈 · 가이드와 같은 `useMyAssignment`).

## 화면 메모

- 헤더 · 본문은 공통 `BackHeader` · `ScreenContent`, 탭 화면 헤더는 노트 게시판 · 회의 도우미와 같은 모양입니다.
- 줄 노트 입력칸은 회의 정리와 같은 에셋(`meeting/summary-lines.svg`)과 `AutoGrowTextarea`를 씁니다. 모눈 배경은 화면마다 높이만 다른 에셋이라 하나(`journal/grid-bg.svg`)를 세로로 반복합니다.
- 사자 · 문구류 일러스트는 홈의 원본 스프라이트 두 장을 Figma 크롭 그대로 씁니다(`JournalIllustration`).
- 이번 주 회의 배너는 이번 주 회의 기록이 있을 때만 보입니다. 목 회의 기록은 10월 날짜라, 회의 도우미에서 오늘 회의를 정리하면 배너가 나타납니다.
- 포트폴리오는 작성 중이 아닌 일지가 2개 이상인 프로젝트만 고를 수 있습니다.

검증: 390px 기준으로 일곱 화면을 Figma와 비교. Chrome에서 홈 → 내 기록 탭(켜짐, 쓴 일지 5 · 읽음 20 · 도움돼요 8) → 돌려받은 일지 상세 → 고쳐서 다시 내기 → 자동 저장 → AI 정리 중 → 미리보기(이름 1곳 가림, 태그 빼기, 보완 질문) → 검토 요청 후 내 기록에 검토 대기로 표시 → 포트폴리오(6조는 비활성) → 요약 만들기 → 다시 만들기 횟수 감소 → 새 일지 빈 칸 안내와 첫 칸 포커스까지 확인. 타입 검사 · ESLint · Prettier · 빌드 통과.
